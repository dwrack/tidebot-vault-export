## P1 — fix first

**Inconsistent www canonicalization.** Five sites resolve on the bare domain (1 hop); AKT, DCKT, GT force `www` via a 2-hop chain (`http→https→www`). The extra hop wastes crawl budget and the inconsistency splits inbound links between www / non-www across the portfolio. Set one standard with FareHarbor (Kevin Schmitt / Jasantha Mari). Most sites are non-www, so standardize the three to non-www, single-hop.

## P2 — worth doing (headroom, not emergencies)

- **Template performance headroom.** Lab scores are uniformly low because the shared theme is heavy (high TBT, large LCP elements). Real users pass today, but if the smaller sites grow traffic and enter CrUX, the heavy theme could start failing field CWV. Worth raising with FareHarbor as a template-level optimization (image compression, defer/async JS, lazy-load). Outliers: **HPB** TBT 4,560ms and **NBB** lab LCP 38.4s are the worst, watch these as traffic grows.
- **DCKT mobile CLS** is the one metric near the edge (lab 0.131, field 0.03). Field is fine; keep an eye if layout changes.

## Entity / Knowledge Graph (via KG API)

- **DCKT is NOT in Google's Knowledge Graph.** The others almost certainly aren't either. This is the real entity gap, not speed. Fix path: Organization/LocalBusiness schema with sameAs (currently missing sitewide), consistent NAP, GBP completeness, then Wikidata. See the DCKT `Schema — Organization + LocalBusiness.md` and `Entity Canon.md`.

## Affects all FH sites (fix once)

- Heavy theme = uniformly low lab scores. A template optimization helps all 7 at once.
- No JSON-LD schema anywhere on the theme (separate finding, see Content Gate report) — the biggest cross-site opportunity.
