Read: Google ranks on field data, which passes. The lab failure is real weight, not noise, but it is not currently costing a Core Web Vitals ranking penalty. It does hurt first-visit mobile users on weak connections and any audit that scores on lab.

Why it is slow (mobile run):
- Page weight 9.6 MB. Biggest: `spnish-moss-dark-2.png` (2016 upload, **1.75 MB PNG**, preloaded as a high-priority image), Unlimited Monthly Kayak Pass image 805 KB, and the `New-Orleans-Zipline-Tour-Kayak-Tour-Combo-image-5.jpg` hero (630 KB) which is **preloaded even though the zipline combo product 301s to the homepage**.
- JavaScript: 2.4 MB unused JS (mobile), 2.9 MB (desktop); script evaluation 3.7 s main-thread. Third parties on the homepage: Elfsight all-in-one reviews widget (about 1.9 s of boot time), OpenCX chat widget (663 KB from unpkg), plus 31 script tags in total.
- Server is fast (root document 8-10 ms, Cloudflare, WordPress VIP). The problem is front-end weight.
- Only 1 of 5 homepage `<img>` tags is lazy-loaded.

## Affects all FH sites (shared FareHarbor / WP-VIP theme: likely, only NKST measured today)
1. **Unused JavaScript of 2.4-2.9 MB and about 2.5 s of main-thread blocking** come largely from the theme's `/_static/` bundle (about 0.6 s boot time on its own) plus site-level widgets. Ask FareHarbor to split or defer the theme bundle. Verify on another FH site before escalating.
2. **Tour/product pages ship breadcrumb schema only.** If the theme controls the Product/Offer output, it affects every FH site, not just NKST. Ask FareHarbor whether the theme can emit Offer/AggregateRating, or use the Schema Markup ACF field per page.
3. **Default meta description 'Have you seen the swamp?'** looks like a theme/site default applied when the SEO description field is empty. Probably NKST-specific text but the fallback mechanism is shared; ask whether other sites show a default string.
4. CSP header is permissive (`'unsafe-inline' 'unsafe-eval'`), and `x-hacker` header advertises WP VIP: informational only.
